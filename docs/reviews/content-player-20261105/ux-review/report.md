# 轻量 UX 任务走查（开放探索）

入口：http://localhost:3000/one-g/solutions/teleoperation/ 。桌面 1440×1000；手机 390×844，Chromium 视口模拟。只读实际页面，未阅读实现源码或历史报告。

## 产品理解与自选任务

这是面向宇树 G1 采购和技术评估人员的 SONIC Link 遥操作方案介绍页。用户很可能先理解套装与部署边界，再通过真实使用和研究演示判断是否值得咨询。

我选择的主要任务是找到“三点 VR 遥操作”研究演示，观察机器人动作，放大观看并回到页面继续阅读。结果：完成。另选与评估演示直接相关的风险点：暂停是否能保留清晰动作帧，方便查看姿态细节。

## 实际路径

1. 看到首屏介绍、技术说明和联系我们；为判断动作效果，继续向下浏览至“遥操作使用实拍”和“遥操作研究演示”。入口与研究候选边界说明可见，未把视频误认为设备控制入口。
2. 看到“三点 VR 遥操作”卡片及播放/暂停、时间轴和全屏图标，选择该卡片。真实观察到视频画面改变，currentTime 递增；并非只依据按钮变化判断成功。
3. 点击第一张卡片的全屏图标。桌面和手机模拟均进入全屏，画面比例保留。再次点击同一图标退出，回到原卡片附近；播放时间保留并继续递增。截图：desktop-stable-fullscreen.png、mobile-stable-fullscreen.png、mobile-stable-return.png。
4. 暂停以查看动作帧：暂停反馈是中央播放按钮和底部时间停止，但桌面画面变为明显模糊；鼠标移出播放器后仍然模糊，出现查看细节的障碍。

## 关键问题（1 条）

### 暂停后动作帧模糊，无法可靠核对姿态细节（犹豫／任务局部受阻）

**观察到的事实：**桌面研究演示第一张卡片正常播放时，人物及机器人清晰（desktop-stable-fullscreen.png）；点击暂停并移开鼠标后，时间停在约 0:01，画面明显模糊且中央覆盖播放图标（desktop-paused-check.png）。另一次暂停退出全屏后约 0:02 也出现同样状态（desktop-stable-return.png）。用户能够继续播放，但无法在停住的当前帧仔细查看身体与机器人对应关系。

**原因推断：**暂停状态可能沿用了用于强调播放入口的模糊视觉处理。未读取源码，不能确定具体机制。

**建议达到的结果：**暂停保留当前清晰帧；播放入口和控制状态可见，同时允许观察动作细节。至少在已播放后的暂停状态中应避免整幅画面模糊。

## 证据边界与未验证

手机模拟中已验证播放、全屏及按钮退出；未据其推断 iOS/Android 真机原生全屏、触摸手感、声音或触觉表现。未检查咨询提交流程、所有视频的完整结尾、刷新恢复进度、弱网和字幕。

开发环境期间遇到一次手机页等待 video 超时及初始空页；主 Agent 确认同期间有共享组件热更新，后续重新导航已能运行，归为环境瞬态，不列产品问题。初轮全页“播放”定位被多个卡片及自动播放状态影响，产生非预期选中；后续限定第一张卡片复核，不据误点报产品缺陷。Playwright Escape 未退出全屏也未计作产品缺陷，实际退出已用播放器按钮验证。
